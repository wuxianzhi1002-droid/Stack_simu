# 知识库自生长流程

## 一句话结论

本目录是 `wiki/` 的流程型总控台，用来把现有研究分类组织成“原始资料 -> 消化沉淀 -> 方法复用 -> 输出应用 -> 复盘回流”的闭环。

## 流程入口

- [[A_原始资料索引]]：从 `../../work/` 进入，登记原始代码、数据、仿真工程、论文、会议记录和输出结果。
- [[B_概念沉淀库]]：沉淀经过理解、归纳和结构化后的项目事实、概念、原理、参数口径和实验结论。
- [[C_方法与Skill库]]：沉淀可复用的方法、流程、prompt、代码使用口径和实验模板。
- [[D_输出成果索引]]：索引报告、方案、仿真总结、训练结果摘要和阶段性结论。
- [[定期复盘]]：记录复盘节奏、待回流问题、过时结论和下一轮整理任务。

## 与现有目录的关系

| 流程层 | 主要承载位置 | 说明 |
|---|---|---|
| A 原始资料 | `../../work/`、[[sources]] | 原始材料留在 `work/`，`wiki/` 只做路径索引和结论引用。 |
| B 概念沉淀 | `01_Projects/`、`02_Literature/`、`03_Methods/`、`04_Experiments/` | 保存已理解、可复查的知识页。 |
| C 方法复用 | `03_Methods/`、`05_CodeNotes/` | 保存可重复调用的方法、参数流程、脚本说明和 prompt。 |
| D 输出应用 | `04_Experiments/`、`06_Issues/`、`../../work/04_results_and_datasets/` | 记录输出成果，原始大文件仍留在 `work/`。 |
| 复盘回流 | `06_Issues/`、[[log]]、本目录 | 把问题、评审、失败经验回流为新的来源、方法或待验证任务。 |

## 使用原则

- 本目录不替代原有 `01_Projects/` 到 `06_Issues/` 分类，而是提供一条流程视角。
- 任何稳定结论都应能追溯到 `../../work/` 路径、实验报告或评审记录。
- 复盘时优先更新索引和链接，再决定是否新建专题页。
