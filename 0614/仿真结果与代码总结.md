## 3. 仿真结果

三种方法的误差统计如下，单位均为 `nm`：

| 方法 | Mean | Std | RMSE | MAE | Max abs | P95 abs |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FFT 固定线性标定 | -1.2490 | 9.9532 | 10.0313 | 7.4944 | 22.4824 | 18.5481 |
| 固定膜厚 LSQ | 7.3598 | 10.0649 | 12.4687 | 7.3599 | 21.6350 | 21.6281 |
| 带膜厚先验联合 LSQ | 7.3600 | 10.0649 | 12.4689 | 7.3600 | 21.6355 | 21.6284 |

本次小规模验证的判据结果：

`WARNING: prior joint fitting did not improve. Check identifiability, prior weight, angle diversity, or film model.`

含义：

- 在当前 `3 process x 5 cavity`、单角度、单偏振的小规模测试下，带膜厚先验的联合拟合没有优于固定线性标定和固定膜厚 LSQ。
- 这不一定说明方法无效，更可能说明单角度光谱中腔长和膜厚扰动的可辨识性不足。
- 脚本最后也提示了后续方向：加入 `angle_axis_deg` 或同时使用 `s/p polarization`，形成 `I(lambda, theta, pol)` 的联合拟合。

## 4. 跨工艺线性系数变化

每个 process 单独拟合：

`L_fft = slope_p * L_true + intercept_p`

结果如下：

| process_id | slope | intercept_um | rmse_um |
| ---: | ---: | ---: | ---: |
| 0 | 1.0007124644 | 0.2662366882 | 0.0045925636 |
| 1 | 1.0008249588 | 0.1312434378 | 0.0000000000 |
| 2 | 1.0006749663 | 0.3149842508 | 0.0053030357 |

统计：

- `std(slope_p) = 6.3735e-05`
- `std(intercept_p) = 0.0777176 um`

这说明不同工艺下 FFT 距离与真实腔长之间的线性关系确实存在变化，固定线性标定并不是完全工艺无关的。

## 6. 仿真脚本结构

脚本位置：

`01_Lumerical_Workflow/validate_prior_joint_fit_lumapi.py`

### 6.1 配置部分

- `FilmLayerConfig`
  - 单个膜层配置。
  - 包含膜层名、厚度参数名、名义厚度、膜厚不确定度。

- `ValidationConfig`
  - 全局配置 dataclass。
  - 集中管理路径、模型名、波长范围、腔长扫描范围、膜层参数、随机种子、LSQ 参数、FFT 参数和缓存参数。

默认脚本配置已恢复为：

- `num_processes = 20`
- `num_cavity_points = 21`

小规模测试通过导入后临时 override 配置完成，没有修改脚本默认值。

### 6.2 光谱和模型构建部分

- `build_axes(config)`
  - 生成 `wavelengths_um`、`freqs_hz` 和 `cavity_axis_um`。

- `stack_layers(config, cavity_um, film_nm)`
  - 根据腔长和膜厚生成 StackRT 层结构。
  - 当前层顺序为 `RefReflector / Air / HSQ / PSS / SOC / TiO2 / Cu`。

- `n_matrix_from_layers(...)`
  - 将层结构转换为 StackRT 所需的折射率矩阵 `n_matrix` 和厚度数组 `thicknesses_m`。
  - `Air` 厚度以 `cavity_um` 输入，转换为 m 后传给 StackRT。
  - 膜厚以 nm 输入，先转为 um，再转为 m。

### 6.3 前向模型部分

- `ForwardSpectrumModel`
  - 前向光谱模型基类。

- `LumapiForwardModel`
  - 当前实际使用的前向模型。
  - 每次调用 `evaluate(cavity_um, film_nm)` 时，通过 `fdtd.stackrt(...)` 生成反射光谱。

- `InterpolatedForwardModel`
  - 为后续插值 surrogate 预留的接口。
  - 当前未启用。

- `LumapiSpectrumCache`
  - 光谱缓存。
  - key 为四舍五入后的 `(L_um, film_nm_tuple)`。
  - 用于减少 least_squares 迭代中的重复 StackRT 调用。

### 6.4 数据生成部分

- `generate_lumapi_dataset(config, run_dir)`
  - 生成多工艺、多腔长的真实 StackRT 光谱数据。
  - 每个 process 随机生成一组共享膜厚扰动。
  - 第 0 个 process 强制为名义工艺。
  - 每完成一个 process 保存 checkpoint。
  - 输出 `prior_joint_lumapi_dataset_*.npz`。

### 6.5 FFT 粗解部分

- `solve_fft_dataset(dataset_npz_path, config, run_dir)`
  - 读取仿真光谱。
  - 对每个 `process + cavity` 光谱调用现有 `solve_npz_fft.py` 中的 `FFTSolver.solve`。
  - 输出 `L_fft_um` 和峰值高度。

- `calibrate_linear_on_nominal_process(cavity_axis_um, l_fft_um)`
  - 使用第 0 个名义 process 建立线性标定：

  `L_true = a * L_fft + b`

  - 该标定随后应用到所有 process，形成 `fft_linear` baseline。

### 6.6 两个 LSQ 拟合部分

- `fit_fixed_film_lsq(...)`
  - baseline 2。
  - 固定膜厚为 nominal，只拟合每条光谱的腔长 `L`。
  - 初值来自固定线性标定结果。
  - 光谱残差使用归一化后的光谱差：

  `normalize(I_model) - normalize(I_meas)`

- `fit_prior_joint_process_lsq(...)`
  - 主方法。
  - 对同一个 process 下的所有腔长点联合拟合。
  - 变量为：

  `x = [L_1, L_2, ..., L_N, delta_d_1, ..., delta_d_M]`

  - 同一个 process 的所有光谱共享同一组膜厚扰动 `delta_d_j`。
  - 总残差由光谱残差和膜厚先验残差拼接：

  `r = [r_spec, prior_weight * delta_d / film_sigma_nm]`

### 6.7 统计和绘图部分

- `compute_metrics(errors_nm)`
  - 计算 mean、std、RMSE、MAE、max abs、p95 abs。

- `write_csv(path, rows)`
  - 保存逐点结果 CSV。

- `plot_outputs(...)`
  - 生成所有结果图：
    - error boxplot
    - error vs cavity
    - error vs process
    - example spectrum fit
    - residual
    - process 线性系数变化
    - prior 恢复膜厚散点图

### 6.8 主流程

- `run_validation(config)`
  - 创建带时间戳的输出目录。
  - 保存 `00_config.json`。
  - 生成 StackRT 数据。
  - 做 FFT 粗解。
  - 做名义 process 线性标定。
  - 做 fixed-film LSQ。
  - 做 prior joint LSQ。
  - 汇总 CSV、JSON、图片和失败日志。
  - 复制脚本到结果目录。
  - 终端打印三种方法的核心误差和 PASS/WARNING 结论。

- `main()`
  - 直接使用默认 `CONFIG` 运行完整规模验证。

## 7. 当前结论和下一步建议

当前小规模验证说明：

- 脚本闭环已经跑通。
- 数据、checkpoint、FFT、LSQ、统计、绘图和失败日志均能正常生成。
- 单角度、单偏振下，prior joint LSQ 没有表现出优于 baseline 的鲁棒性。
- 跨 process 的线性系数有可测变化，说明固定线性标定存在工艺依赖风险。

建议下一步：

1. 用默认 `20 process x 21 cavity` 跑完整规模验证。
2. 如果 prior joint 仍不能改善，加入角度维度 `angle_axis_deg`。
3. 进一步同时使用 `s/p polarization`，让拟合目标从 `I(lambda)` 扩展为 `I(lambda, theta, pol)`。
4. 如果完整规模运行过慢，再实现 `InterpolatedForwardModel`，用局部网格或 surrogate 替代每次 LSQ 迭代直接调用 lumapi。
